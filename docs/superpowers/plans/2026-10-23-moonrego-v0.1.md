# MoonRego v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a pure MoonBit Rego v1 parser, compiler, bounded evaluator, and CLI for a documented practical subset.

**Architecture:** Source text becomes spanned tokens, a syntax AST, and then a checked evaluation program. Evaluation treats each body expression as a transformation from one binding environment to zero or more environments, so undefined values, iteration, and backtracking are represented without confusing undefined with JSON null.

**Tech Stack:** Local verification on 2026-10-24 used `moon 0.1.20261023`, `moonc v0.10.17+d971670cd`, and `moonbitlang/core@0.10.17+d971670cd`; Apache-2.0. The documented default `moon upgrade` channel (without `--dev`) completed successfully and `moon version --all` still reports 0.10.17. The [stable command reference](https://docs.moonbitlang.com/en/stable/toolchain/moon/commands.html) labels `--dev` as the development version option. The [official update index](https://www.moonbitlang.com/updates) still lists v0.10.14 as its latest named release, so release-note naming lags the installed stable-channel build. CI must print its actual `moon version --all` result; do not infer the remote version before a run.
